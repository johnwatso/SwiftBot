SwiftBot 1.22.5

Version 1.22.5 · Build 2026080715

The Announcer starts reading sooner, stops losing long messages, and finally leaves an empty channel. Plus an AI Bots page in the Web UI.

🔊Faster Reads, Nothing Silently Dropped

Announcements used to take about six seconds to begin, and longer ones never arrived at all.

  • Reads begin sooner: A message arriving into an idle queue no longer waits out the batching window, and the fallback voice is resolved once instead of on every read — roughly 1.4 seconds off each announcement.
  • Long messages are read, not discarded: The reading cap rises from 300 to 1000 characters, about a minute of speech. Anything over the old cap was previously skipped in silence, with no indication in Discord that it had been dropped.
  • You can hear when a read was trimmed: Trimmed announcements now end with a spoken "message continues". The old ellipsis was never voiced, so a trimmed read sounded exactly like the bot cutting out mid-sentence.
  • Smart shortening removed: The "Smart shorten with Apple Intelligence" toggle is gone. On-device rewriting of a typical announcement takes 5–8 seconds — far longer than the read it delayed — so it never completed within its deadline and only served to drop the message. Shortening is now instant and deterministic. Configs that had it enabled keep reading long messages, trimmed.

👋Until-Empty Actually Leaves

Announcer configs set to "Until last person leaves" could stay parked in an empty channel indefinitely.

  • Other bots no longer hold the channel open: A music bot or second integration sitting in the channel counted as a person, so the last human could leave and SwiftBot would stay. Bots are now excluded — including SwiftBot itself.
  • Moving out counts as leaving: If the last member switched to another voice channel rather than disconnecting, the emptiness check never ran. Channel-hopping now releases the bot the same way disconnecting does.
  • Survives a reconnect: While the bot's own user ID was still being resolved after a reconnect, SwiftBot counted itself as a member and could never conclude the channel was empty.

🤖AI Bots in the Web UI

The Apple Intelligence surface from the Mac app, available remotely.

  • Same controls, in the browser: Status, personality presets, reply rules, and capability tiles now mirror the native app.
  • Conversation memory: Review stored conversations with their message counts, and clear memory per scope.

🛡️Voice Connection Hardening

Continued work on the failure mode where the bot looks connected but nobody can hear it.

  • No silent connections: Voice WebSocket writes and UDP datagram completions are bounded, so a stalled network operation can no longer leave the bot connected and mute instead of reconnecting.
  • Cleaner recovery: A stale playback failure from an old connection can no longer re-pause a queue that has already recovered, and speaking updates are ordered so an old "stopped speaking" cannot silence a newer read.
  • Secure media transitions: DAVE fails closed at gateway receipt time and keeps ordered ownership through its native work, with a bounded watchdog on the transition path.
  • Announcer health: Queue depth, current phase, and retry activity are surfaced so a stuck announcer is visible rather than inferred.
