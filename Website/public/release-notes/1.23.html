SwiftBot 1.23

Version 1.23 · Build 2026082212

A voice-reliability release for the Announcer, with targeted fixes for repeated reconnects when channel membership changes and quieter, safer recovery across clustered bots.

🔊Announcer Reconnect Loop Fixed

A delayed acknowledgement from an older voice disconnect could collide with a new join and repeatedly restart recovery.

  • Member joins no longer trigger endless reconnects: SwiftBot ignores a stale self-disconnect acknowledgement while an active voice recovery is already in progress, preserving the retry budget instead of resetting and starting over.
  • Recovery remains bounded: The until-empty voice path now has regression coverage for delayed disconnect events, including the sequence that previously appeared when another person joined.
  • Updated secure voice transport: SwiftBot now uses libdave-swift 3.0.1, incorporating the latest DAVE session fixes.

🔕Quieter Cluster Failover

Only the active output owner should create visible Discord activity during recovery.

  • No duplicate reconnect noise: Standby instances are blocked at the service boundary from registering commands or sending typing notifications.
  • Safer ownership transitions: Output gates remain enforced even if a higher-level caller accidentally attempts an active-only Discord operation.

🛡️Security and Admin Hardening

Cluster and web-administration boundaries now fail more predictably under malformed or replayed traffic.

  • Replay protection outlives the clock-skew window: Previously accepted cluster nonces remain blocked for long enough to prevent a replay at the edge of the permitted timestamp range.
  • Encrypted mesh traffic fails closed: Invalid secure envelopes are rejected instead of being reconsidered as plaintext cluster messages.
  • Tunnel credentials stay out of process arguments: Tokens are passed through the child process environment.
  • Admin authentication is regression-tested: Valid, expired, malformed, and tampered session tokens are covered with isolated test signing keys.

⚙️Concurrency Cleanup

Media and diagnostics state is now better isolated under concurrent voice activity.

  • Media diagnostics are synchronized: Debug recording state can no longer race when voice callbacks arrive concurrently.
  • HLS packaging respects queue isolation: AVFoundation capture state remains confined to its processing queue without crossing unsafe concurrency boundaries.
  • Shared Discord rate limiting: REST traffic uses a bucket-aware limiter so concurrent services cooperate with Discord's rate limits.
