SwiftBot 1.24

Version 1.24 · Build 2026082810

A feature release: Game Tracker arrives as a new service, the Announcer gains a read-aloud thread and departure announcements, and every integration now lives on one Settings page.

🎮Game Tracker

A new service that follows linked game accounts and posts changes to Discord. Off until you switch it on.

  • Ranked-score tracking: Add game profiles with their own Discord destination channel, and SwiftBot posts a grouped embed when a tracked score moves. Baselines are recorded silently, so the first check and each new season never produce a burst of noise.
  • Play sessions from Discord presence: Optionally announce when a linked member starts and finishes a session. Brief client restarts are absorbed by a grace window, very short sessions are discarded, and the summary is built from real match data where the provider can supply it.
  • Provider-neutral by design: Providers declare their own authentication style, base URL and capabilities, so a provider that cannot report a ranked score is never asked for one. finals.id ships as the first provider.
  • Available in the web admin too: Game Tracker appears in the Services sidebar with status, tracked players, recent activity and a manual Check Now.
  • Daily checks stay on Primary: Polling runs only on the active node, with catch-up at startup if a scheduled check was missed.

🧵Announcer Read-Aloud Thread

/announce join now opens a thread where anything typed is spoken into the voice channel.

  • Type to speak: Anyone who can see the thread can post and be read aloud, with no configuration needed — useful for someone without a microphone.
  • Same rules as any other source: The thread feeds the existing announcer pipeline, so it inherits link stripping, long-message shortening, emoji-spam filtering and the self-message guard.
  • Flood protection: A 400-character cap and a per-author cooldown keep one person from monopolising the queue, and announcer commands are not read back to the room.
  • Tidied up on leave: The thread is archived when the announcer disconnects, which collapses it without destroying what anyone wrote.

👋Departure Announcements

The Announcer now says when someone leaves, not only when they arrive.

  • Leaving is announced like joining: Human departures from the active Announcer channel are spoken, including moves to another voice channel. Bot and SwiftBot departures stay silent.
  • The goodbye finishes first: Until Empty waits for a final departure announcement to play before it pauses or disconnects.

🔊Voice Reliability

Targeted work on the connected-but-silent failure that could follow a recovered secure-media session.

  • One-shot recovery after a long idle: Following a real DAVE failure and a successful rejoin, SwiftBot rebuilds the media path once before the next announcement — but only if the recovered session has been idle for 20 minutes. Healthy sessions never reconnect just because they are quiet, and the queued message survives the refresh.
  • Rejoins must prove themselves: An automatic rejoin now has to stay healthy for 30 seconds before its retry budget is refunded, so rapid participant churn can no longer loop indefinitely through fresh first attempts.
  • Honest diagnostics: Exported logs preserve the underlying DAVE failure across teardown, mark earlier failures as historical once a connection recovers, and state plainly that keepalive success proves a local write rather than delivery to Discord.
  • Updated Opus codec: SwiftBot now uses swiftbot-opus 0.2.1.

🔗Settings › Integrations

One page that answers what SwiftBot can connect to, what is connected, and what needs attention.

  • Everything in one place: Game-tracking providers and companion apps now share a single overview, with credentials and advanced options in per-integration sheets.
  • SwiftMiner pairing moved: SwiftMiner is now paired from its own sheet on the Integrations page instead of a separate preferences tab.
  • Credentials in the Keychain: Provider tokens are stored per provider in the Keychain and never written to settings.json. Existing finals.id credentials migrate automatically on first launch.

🔧Fixes

  • Game Tracker renders in the web admin: A mistyped helper stopped the tracked-player list and recent activity from drawing as soon as any player was configured.
  • Player identifiers are escaped in session lookups: Identifiers containing spaces or punctuation no longer break the request that fetches a session's matches, which previously reduced summaries to duration alone.
  • Read-aloud cooldown counts only spoken messages: A filtered post — SwiftBot's own, a webhook, or a bot when those are skipped — no longer spends the author's cooldown and silences the message that follows.

📦Release Notes

  • Requires macOS 26 or later on Apple silicon.
  • Game Tracker is off by default. Both the daily check and play-session tracking are opt-in, and a provider needs its credentials and endpoint configured in Settings › Integrations before it will run.
  • Updates are delivered through Sparkle and verified with the SwiftBot signing key.
