SwiftBot 1.22.7

Version 1.22.7 · Build 2026081814

This hotfix keeps the Announcer in the room through ordinary Discord gateway reconnects, so listeners do not get a distracting leave-and-rejoin notification.

🔄Quiet Background Reconnects

A brief main Discord gateway drop used to make SwiftBot identify as a new session, which could interrupt the Announcer's voice membership.

  • Gateway sessions now resume: SwiftBot uses Discord's session-resume protocol after a transient drop, preserving the existing voice state rather than leaving and joining the channel again.
  • No unnecessary Discord ding: Players should no longer hear the bot's leave/rejoin notification during a normal reconnect.
  • Safe fallback: If Discord rejects the old session, SwiftBot falls back to a fresh connection as required.

🔊Announcer Recovery Stays Intact

Voice handshakes can be replayed while Discord is stabilising after a reconnect.

  • Duplicate handshakes are harmless: A replay for the already-active voice session no longer tears down speech with a busy-pipeline error.
  • Fresh handshakes recover cleanly: If Discord sends genuinely new voice credentials while an old pipeline is still winding down, SwiftBot uses its normal controlled rejoin instead of failing the Announcer.

🩺Reconnect Evidence in Exports

The next report will identify a reconnect instead of merely showing that one happened.

  • Diagnostic exports retain the latest 20 main-gateway reconnect causes, close codes, generations, and retry delays.

🚢Release Details

  • Updated MARKETING_VERSION to 1.22.7 and CURRENT_PROJECT_VERSION to 2026081814.
  • Added regression coverage proving a reconnect resumes the prior Discord session rather than identifying again.
