SwiftBot 1.22.9

This release is about telling the truth. Two subsystems had learned to report a healthy result while quietly sitting on a stale one, and both are now honest about what they actually know.

An Honest Overview Dashboard

- The Operational Status header no longer sticks on “Action Required.” A close code from a socket SwiftBot had retired itself was being attributed to the live connection, so one routine reconnect pinned the dashboard to a critical state for the rest of the session.
- Close code 1001 is no longer treated as a fault. It means “going away” — what Discord sends when it cycles a gateway host, and what SwiftBot sends when it replaces its own socket.
- Resumed sessions clear the last close code. Most reconnects resume rather than re-identify, so a transient close previously stayed on screen until the bot was restarted.
- Only close codes an operator can act on (4004, 4010–4014) now raise a critical alert, and each names its actual remedy instead of a blanket “check token, intents, and permissions.”

Patchy Stops Trusting a Stale Sitemap

- AMD's sitemap routinely lags the live release notes by weeks and skips releases outright. A fetch that settled for whatever it offered was indistinguishable from a genuine “no new driver” result.
- The sitemap is now a floor, not the answer: the scan walks release months backwards from today until it finds a live release, tolerating AMD's skipped patch numbers rather than stopping at the first gap.
- Probes are HEAD requests with a per-fetch cap, 404s are treated as answers instead of being retried under further User-Agents, and a page already verified while probing is reused rather than downloaded twice.
- Update sources can now attach non-fatal diagnostics to a result, and Patchy writes them to its log on cycles, pulls, and test sends, so scraping decay is visible before it becomes silently missed releases.

Voice Encryption

- Upgraded libdave-swift to 3.0.0, adopting its structured diagnostic events and export-safe post-mortem traces while keeping the acknowledged Discord gateway outbox contract.
- Exports now carry the external sender state, MLS roster members Discord never announced in the voice session, structured failure classifications, and the recent event trace.
- Persisted DAVE identities are purged when the bot account is signed out or switched, so a new account never inherits the previous one's MLS state.

Release Details

- Updated MARKETING_VERSION to 1.22.9 and CURRENT_PROJECT_VERSION to 2026082108.
- Added regression coverage for gateway close-code classification and for clean closes not being reported as faults.
- Restored three test files that existed on disk but had never been added to the test target; the suite now runs 385 tests.
- The DAVE 3.0.0 upgrade ships without a disposable-channel rehearsal of the MLS transition path, which cannot be exercised offline. The widened diagnostics above exist to make the first live join legible if it misbehaves.
